# ADR-010：Phase 3 质量治理采用 Dry Run 与审批门禁

- 状态：Accepted
- 日期：2026-08-03
- 关联契约：[架构契约](../architecture-contract.md)、[Phase 3 质量治理](../phase3-quality-governance.md)

## 背景

TTL 填充和数据清理属于生产 Redis 修改操作。风险扫描只能发现候选范围，不能直接转化为写入
命令；治理动作必须可解释、可暂停并可审计。

## 决策

Phase 3 所有治理任务统一使用：

```text
规则定义 → Dry Run → 影响报告 → 人工审批 → 限速执行 → 结果校验
```

首个实现为 TTL 治理，后续补齐独立的数据清理任务。TTL Dry Run 使用 `SCAN` 和 TTL 元数据，
执行阶段只对仍然无 TTL 的 Key 调用 `EXPIRE`；清理任务执行阶段只调用 `UNLINK`，并冻结
`impactLimit`。两类任务各自拥有运行记录和分片 cursor，不能互相复用。暂停、恢复、取消和
版本冲突由 Platform 控制，Worker 不绕过审批。

## 后果

- 降低误操作风险，并能在执行前给出影响范围。
- 执行吞吐低于直接批量写入，但可以暂停、恢复和定位跳过原因。
- 数据清理使用同一门禁，但采用独立任务、影响上限和独立审计动作；删除后不提供平台自动恢复。
