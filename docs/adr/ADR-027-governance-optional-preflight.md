# ADR-027：治理预检可跳过与可暂停

状态：Active。范围：Platform TTL 治理、数据清理，不涉及 Sync Worker。

## 决策

- 预检可由已授权运维显式跳过，必须填写原因并明确确认。单一 `skip-dry-run-and-start` 请求在同一事务内完成执行授权（APPROVED）、状态转换（RUNNING）、审计追加及 APPLY Job 入队；不再要求额外点击审批。
- 运行中的预检可暂停为 `DRY_RUN_PAUSED`；恢复只继续只读预检，不能走正式执行入口。
- 跳过只允许在新建或预检暂停状态。正在预检时必须先暂停，等待执行 Job 退出。
- 控制动作继续要求 Idempotency-Key / If-Match。审计保存身份快照、状态、集群/DB、数值预算、规则指纹和原因，不保存实际 Key、规则原文、密码或 value；填写原因不得包含敏感数据。
- 预检运行记录使用 DRY_RUN 状态，正式执行使用 RUNNING。暂停保留该运行的游标/计数；正式执行新建独立运行，不能继承预检预算或游标。历史未区分阶段的记录不作为预检续跑依据。
- 新 Job 携带任务版本和 resume 标志；旧版本 Job 不执行、不更新新阶段状态。恢复/跳过前检查仍在执行的 Job，避免快速切换造成重叠。
- 常规预检流程仍保留审批；跳过流程的单次风险确认就是执行授权。两条路径均保留限速、数量上限、暂停/取消和 Redis 侧条件检查。暂停不回滚已修改的数据，当前批次可能尚在收尾。预检暂停不与执行暂停共用状态；继续预检通过原 dry-run 入口。

## 边界及部署

现有状态列为 VARCHAR，无 schema 变更。新状态需前后端同时发布。升级前停止旧版治理任务并等待退出，禁止新旧执行器混跑同一治理任务。
扫描页计数与游标同事务提交。每个执行 Job 使用可识别的独立 run_no，重领同一个 Job 时可恢复同阶段未完成的运行。运行记录和游标依旧是当前治理机制，不宣称 Redis 写入与 MySQL checkpoint 跨系统 exactly-once，也不新增自动失败重跑。
本次不改变 Key 分布分析的恢复语义，不实现业务流量切换或企业授权平台。
