# ADR-004：同步失败关闭与人工确认重建

- 状态：Accepted
- 日期：2026-07-29
- 关联契约：架构契约第 4 节

## 背景

Redis 的增量命令包含 `INCR`、`LPUSH` 等非幂等写入。来源 backlog 失效、未知 RDB 类型、未知
命令、spool 损坏或过滤无法等价拆分时，继续或自动重置目标都可能造成静默数据损坏。

## 决策

不能安全证明恢复正确时，任务进入明确 `BLOCKED` 状态和错误码（例如
`BLOCKED_REQUIRES_FULL_RESYNC`、`BLOCKED_FILTER_BOUNDARY`），不自动 flush 目标、不跳过
未知内容、不降级为无认证。新的全量只能由操作人重新预检、确认写隔离和确认清空后启动。

## 后果

- 一致性优先于短期可用性；任务可能需要人工介入。
- 预检查、命令能力清单、阻塞原因和事件记录成为必需的运维界面。
- 对可安全重放的全量 `RESTORE REPLACE` 允许从完整 RDB spool 重放，但仍经过 fence。

## 替代方案与取舍

- 自动清空并重新全量：恢复快，但会在错误场景中破坏目标或覆盖已恢复数据。
- 忽略不支持类型/命令：表面完成，实际产生不可见数据差异。

## 落地与验证

对 backlog 失效、replId 变化、Module/未知编码、过滤混合命令、spool 损坏、Worker 接管与
磁盘满注入测试；断言不会执行自动清空。
