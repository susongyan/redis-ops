# ADR-003：集群内置加密连接秘密

- 状态：Accepted
- 日期：2026-07-29
- 关联契约：架构契约第 6 节

## 背景

Phase 1 不接 KMS，且一个集群的发现、同步、治理和未来访问层先共用同一连接账号。独立凭证
资源与多用途绑定会增加集群录入和运维复杂度，当前没有复用需求支撑。

## 决策

每个 Redis 集群在内部 `redis_cluster_secret` 中维护可选 ACL 用户名和 AES-256-GCM 密文。
该表不是独立业务 CRUD 资源。所有消费者通过 `RedisConnectionProfileProvider.get(clusterId)`
获取连接信息；返回的密码使用后清零。

## 后果

- 集群新增/编辑页面直接配置认证，密码为 write-only；更新密码不需要更新关联任务。
- 无认证集群不保存秘密；关闭认证时清除用户名和密文。
- 密钥环由 `REDIS_OPS_CREDENTIAL_KEYS` 注入，第一把钥匙用于写入，其余只读旧密文。
- 后续若出现应用级 ACL、用途隔离或跨集群凭证复用需求，必须新增 ADR 和迁移，而不是在 API 中
  临时暴露秘密资源。

## 替代方案与取舍

- 明文数据库保存：拒绝，泄露面不可接受。
- 外部 KMS：安全边界更强，但不符合当前部署简化目标。
- 独立凭证资源 + 五用途绑定：扩展性更高，但当前用户操作和模型复杂度不成比例。

## 落地与验证

测试 AES-GCM 随机 IV、密钥轮换、篡改失败、API/日志脱敏和 Worker 本地解密；禁止密码进入
REST、审计、任务 payload 或 spool 元数据。
