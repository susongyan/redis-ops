# ADR-007：校验差异保留 Key 名称用于排障与数据订正

- 状态：Accepted
- 日期：2026-07-29
- 取代：[ADR-006](ADR-006-data-validation-sampling-and-big-key-safety.md) 中“不保存原始 Key”的限制
- 关联契约：[架构契约](../architecture-contract.md)

## 背景

只保存 Key 哈希可以降低元数据暴露面，却无法让运维人员定位缺失、额外或不一致的数据，必须在 Redis 中重复扫描后才能订正。数据校验的用途之一正是为同步验收和人工修复提供可执行的定位信息。

## 决策

`validation_difference` 保存差异 Key 名称和 SHA-256 摘要。正常 UTF-8 Key 原样保存；包含控制字符的二进制 Key 使用 `base64:` 编码保存，避免 API 和页面渲染歧义。

Redis Value、序列化内容、密码和密文仍不得保存。日志、异步事件、指标和审计也不得记录 Key 或 Value；Key 名称仅出现在差异查询 API、详情页面和受限数据库表中。

## 后果

数据订正可以直接使用报告中的 Key 名称，而不需要再次全库扫描。相应地，Key 名称被视为业务敏感元数据：在 RBAC 尚未落地前，生产部署必须通过网络、平台账号和数据库权限限制结果访问范围。

现有历史报告没有 Key 名称时，页面显示“历史记录仅保留摘要”；新运行记录从 V15 migration 起保存 Key 名称。
