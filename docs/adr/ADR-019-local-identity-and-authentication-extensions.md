# ADR-019：本地用户授权与企业认证扩展边界

- 状态：Accepted
- 实现状态：本地认证、授权与 JDBC 会话已实现；企业适配器仅预留
- 日期：2026-09-14

## 决策

身份与准入属于 Platform 自有领域，不进入 sync-contract，不影响 Worker 租约。
首期实现本地账户、ADMIN / OPERATOR 两种角色；企业 OIDC / LDAP 仅预留认证端口，
不提供企业登录入口、不宣称适配已实现。认证适配器只返回来源和稳定身份，不授予角色。

用户与身份绑定独立建模。外部身份由来源、提供方和稳定标识唯一确定，不按邮箱、显示名
自动合并。本地登录名规范为小写 ASCII；外部标识保持原始大小写。企业新身份未来进入
PENDING，由本平台批准。禁用用户无论认证来源均不能访问业务接口。

密码只存 BCrypt 哈希，12–72 UTF-8 字节，不截断、不写日志、审计或幂等摘要。
默认管理员仅首次事务初始化，部署提供密码，无通用默认密码。首次/重置后必须改密。
最后一个可用本地管理员的保护必须在数据库串行事务内完成，不能仅依赖对象检查。

采用 Spring Security 和 JDBC 会话；每个业务请求读取本地状态和授权版本，撤权后拒绝
旧会话。认证不可用时失败关闭。HTTP 写请求启用 CSRF，身份不信任 X-Operator。
默认会话空闲 30 分钟、绝对 8 小时。企业禁用即时联动不属于首期能力。

## 数据与迁移

后续递增 Flyway migration 增加用户、身份、本地凭据、会话、初始化和限速记录。
同时更新 sql/latest 完整包。未完成认证闭环前不变更本地运行进程的认证行为。
历史审计保留原文，新审计和幂等主体使用内部用户 ID，不自动关联历史名称。

## 交付与验证

先交付模型及认证基础，再完成用户管理和前端，最后联调迁移、会话、CSRF、真实审计。
任何阶段完成不等于已可安全上线；上线必须等待所有业务 API 的认证覆盖测试通过。
不得使用匿名后门使旧脚本继续工作；脚本需更新为真实登录与 CSRF。
