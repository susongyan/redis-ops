# ADR-009：企业内部风险扫描与慢日志保留原始 Key

- 状态：Accepted
- 日期：2026-07-31
- 关联契约：[架构契约](../architecture-contract.md)
- 取代范围：细化 ADR-007 的 Key 保留边界，并取代此前“风险扫描仅保留 Key Hash”的约束。

## 背景

风险扫描、数据校验和慢命令排障需要直接定位业务 Key。仅保存 Hash 会使人工订正和跨系统查询成本过高。平台仅部署在企业内部网络，业务确认可在受控页面显示原始 Key。

## 决策

平台可在 MySQL 的风险发现、校验差异和慢日志摘要中保存并通过内部页面/API 返回 Redis Key。完整 Redis Value 仍禁止保存、返回、打印或写入审计。

原始 Key 的边界：

- 可进入受控业务表和内部页面/API；默认保留期由各能力的清理任务实现。
- 禁止进入应用日志、异常消息、审计、Prometheus 标签、异步任务 payload、Webhook、导出模板和外部通知。
- 不得把 Key 与 Redis 密码、密文、主密钥或完整 Value 一起写入任何记录。
- RBAC 接入后，原始 Key 查询必须纳入资源级授权和查询审计。

## 后果

排障效率提高，但数据库包含业务标识数据，需要后续实施保留期清理、查询审计和 RBAC。风险扫描和慢日志实现必须从 `key_hash` 扩展到受控 `key_name` 字段，历史 Hash 记录继续可读。
