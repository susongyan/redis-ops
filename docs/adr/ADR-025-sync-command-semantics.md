# ADR-025 业务 Key 过滤与同步命令语义扩展

状态：Accepted（分阶段实施）。阶段一至四核心实现已完成；显式 v2 多 Key、v3 源事务与页面扩展已接入，
生产发布须完成剩余集成门禁，不表示当前运行版本已升级。

## 背景

共享 Redis 按业务拆分需要范围内完整复制。现有硬阻塞清单限制了多 Key 和 Lua effects 的可用性；
直接取消限制又无法保证过滤、Slot 路由和 checkpoint 恢复正确。

## 决策

- Worker 拥有版本化命令语义注册表及处理器；不复用 Console 命令目录，不共享 Platform 实现。
- 按读写 Key、范围依赖和目标拓扑判断；混合范围默认阻塞，不能静默丢弃范围内写入。
- 复制事务作为不可拆分单元；首期不支持混合范围事务或跨 Slot 原子事务。
- 先补 EXEC 局部错误及执行结果不确定的持久化确认机制，再扩大命令支持。
- Key 规则及策略绑定任务版本；旧任务不自动升级，未知命令继续失败关闭。
- 数据校验用于验收，不替代同步执行与恢复协议的正确性。
- 增量 FLUSHDB/FLUSHALL 会删除目标确认状态，所有拓扑均禁止；保留历史允许字段的读取兼容，
  但它不再授予执行权限。首次全量初始化经确认的清空流程不受影响。能力契约升级为 0.1.1，
  Platform 与 Worker 同步依赖，不覆盖原 0.1.0 artifact。

## 所有权与失败边界

阶段二契约版本为 `0.2.0`：新增显式 `policyVersion=v2`，默认及历史缺省值仍为 v1。
v2 首批 15 种多 Key 命令只有在读写范围、参数和同 Slot 要求成立时执行；COPY 仅允许
源 DB 内复制，并移除显式同 DB 选项以适配目标 DB 映射。预检查及执行前探测实际源、目标
Redis 版本，仅接纳 6.2 / 7.x。原文脚本、源事务和未知命令仍阻塞。
Worker 领取 SQL、能力声明和命令规划必须同时支持 v2；不得只升级 Platform。

阶段三使用 `sync-contract:0.3.0` 与显式 `policyVersion=v3` 接入源事务，v1 / v2 不自动扩大范围。
事务内 SELECT 仅更新源 DB 状态；成功 checkpoint 不进入事务中间。读取、组装和排队设置独立容量界限，
spool 使用流式回放；详情及未完成发布门禁见[事务执行记录](../sync-source-transactions-v3.md)。

阶段四新建页面显式默认 v3，API 缺省仍保留 v1。创建任务时，空包含规则或全星号包含规则
必须显式传 `confirmFullKeyspace=true`；这是新增安全确认，旧全范围调用方必须升级，
不是自动兼容放行。规则限制每类 100 条、每条 1024 UTF-8 字节。示例只留在浏览器短期内存。
固定容量统计为进程观测，不新增逐任务持久事实或恢复依据；交付说明见
[第四阶段记录](../sync-business-key-delivery.md)。

不新增运行服务。Platform 保存任务意图和规则快照；Worker 执行、路由并管理目标确认状态；
目标 Redis 仍为 checkpoint/fence 的最终事实，MySQL 租约不替代目标保护。
未确认批次只能阻塞核实或显式重建，不能自动重放非幂等命令或自动清空目标。
第一阶段协议和兼容基线以[目标批次确认](../sync-target-batch-confirmation.md)为准；
MOVED/ASK、主从切换及生产网络压测仍是后续发布门禁，不因决策接受而免除。
