# ADR-012：模型无关的 AI 分析与 Agent 协作

- 状态：Accepted
- 日期：2026-08-11
- 决策者：Redis Governance Platform
- 关联契约：架构契约第 6、7、8 节

## 背景

平台未来需要分析告警、同步延迟、数据校验、大 Key 风险和历史线上故障。模型、Agent 框架和部署方式可能变化，不能让业务领域直接依赖某个模型 SDK 或厂商协议。

## 决策

平台业务层定义统一的 `AnalysisAgentClient`、`AnalysisRequest` 和 `AnalysisResult`。A2A、ACP、HTTP/JSON 和规则引擎均作为基础设施适配器接入。

A2A 用于远程 Agent 协作和异步任务；ACP 用于兼容企业内部 Agent 平台；指标、告警、同步状态和历史案例通过受控只读 Tool Gateway 提供。Agent 不直接访问 Redis、MySQL 或凭证，也不能直接执行生产写操作。

分析上下文必须结构化、可脱敏、可审计。历史故障作为经过质量标记的检索案例输入，不默认作为无审查训练数据。Agent 不可用时回退到规则分析，不影响治理主流程。

## 后果

优点：可以替换模型和 Agent 平台；支持本地、云端和规则模式；跨团队 Agent 可以异步协作；生产动作仍由平台既有安全流程控制。

代价：需要维护协议适配器、统一结果契约、Agent 注册配置和调用观测；A2A/ACP 版本变化需要隔离在适配层。

## 替代方案与取舍

- 直接绑定某个模型 SDK：实现快，但迁移和数据边界成本高，不采用。
- 只使用 A2A：不适合简单模型调用和规则分析，不作为唯一协议。
- 让 Agent 直接调用 Redis 工具：权限和审计边界不可控，不采用。

## 落地与验证

- 规则 Provider 在无外部模型时返回可用结果。
- HTTP、A2A、ACP Adapter 均转换为统一请求和结果结构。
- 超时、取消、重试、降级、幂等和审计测试覆盖。
- 验证 Agent 请求中不包含密码、密文、主密钥或完整 Value，Agent 结果不能直接触发生产写操作。
