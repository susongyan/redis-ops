# Phase 1 开发任务拆分

## 当前进度（2026-07-27）

M1“资产闭环”已经完成并通过本地真实环境验收。完成范围包括：

- Region/IDC 字典、Redis 集群、应用及应用集群绑定的 CRUD、筛选、乐观锁和软删除。
- 集群内置连接认证，密码使用 AES-256-GCM 加密；API、日志、审计和异步任务不暴露秘密。
- Standalone、Sentinel、Cluster Endpoint 校验、保存前连通性测试和异步拓扑发现。
- 同进程 Worker 的持久化任务、租约领取、失败重试和节点快照原子刷新；发现失败保留最后一次成功快照。
- 所有资产写操作支持 `Idempotency-Key`，资源更新和删除同时使用 `If-Match`；审计日志可筛选查询。
- 集群、机房、应用、拓扑、认证状态和审计日志管理页面。

验收命令为 `mvn test`、`cd frontend && npm run build` 和 `./scripts/asset-smoke.sh`。真实 Redis
验收覆盖无认证 Standalone、ACL Standalone、Sentinel 和三主节点 Cluster，发现节点数分别为
1、1、2、3；同时覆盖错误密码、重复提交、失败快照保留、审计去重和秘密脱敏。

Phase 1 整体尚未完成。M2 已选择自研 Java 同步引擎：Standalone 全量 RDB、增量 RESP、
加密 spool、目标 checkpoint/fence、租约接管、暂停恢复、RPO 指标及任务页面已经形成闭环；
Sentinel 单通道选主与 failover 重连代码已经完成。Cluster 多 master/slot 路由、多版本与
性能故障矩阵仍是退出项。Standalone 已通过 Redis 5.0、6.2、7.4、8.0、8.4 同版本容器
矩阵；跨版本、Sentinel/Cluster 和压力故障矩阵仍待完成。RBAC 按既定决定延期。

## 3. 优先级与并行轨道

P0 为 001–008、101–107、201–207、301–303；前端 108/208 可与后端按 mock API 并行。真实同步工具尚未选定时，先以契约测试和 mock 完成主链路，P1-207 单独作为集成风险项，不阻塞资产模块。

## 4. Epic 验收场景

资产：创建带加密连接凭证的集群，触发发现后看到节点与 slot；失败时仍展示上次成功数据；绑定应用后可按应用/负责人反查。

同步：创建任务后检查通过才能启动；重复启动不产生两个外部任务；暂停后恢复到原阶段；Worker 中断后租约接管；每次动作均能从事件和审计定位操作者。

上线：任何 API/日志不出现明文凭证；核心告警可触发；数据库恢复演练满足确认后的 RPO/RTO。RBAC 验收随 P1-007 延期。

## 5. 待产品/技术确认（不阻塞骨架）

1. 首个同步工具及其控制接口（RedisShake、内部工具或其他）。

3. 首期支持的 Redis 拓扑类型及最低/最高版本。
4. 生产规模基线：集群数、节点数、并发同步数和资产刷新频率。
5. “停止”语义采用可恢复 pause 还是不可逆 cancel；当前模型两者分开。
