# 审计操作内容

保持既有统一审计动作范围，不新增 Console 执行、扫描或分析的审计接入。

已实现的详情：

| 操作 | 内容 |
| --- | --- |
| 命令新增、定义或策略修改 | 命令名、启用、分类、风险、审批、路由、容量等前后差异，变更原因；参数定义只标记变更 |
| 集群新增、修改、删除 | 基础属性、IDC、负责人、状态；地址只标记变更，不记录原文 |
| 应用新增、修改、删除 | 编码、名称、负责人、业务线、状态 |
| 应用绑定、解绑 | 应用与集群 ID、客户端类型和版本；连接池配置只标记变更 |
| 同步创建、控制、运行限制更新 | 任务号、源/目标集群及 DB、状态、控制意图、速率、带宽、spool、并发、pipeline 的变化 |
| 用户新增、修改 | 显示名称、角色、状态；不含密码或哈希 |

其它已有审计动作保持基础信息。本次不承诺全量失败请求审计或所有动作均有详情。
列表增加“操作内容”，详情展示“字段 / 操作前 / 操作后”和可用的变更原因。
空值显示“—”，历史或未接入的记录显示“未记录详情”；无差异显示“无可展示的字段差异”。

数据库 V33 为 audit_log 增加可空 details_json。API 的 AuditLog 增加可空 detailsJson 字符串，
内容为 `{summary,changes:[{field,before,after}],reason}`。业务与详情在同一事务内写入。
内容来自显式字段映射，不复制请求、凭据对象、Redis Key/value、连接串、过滤规则或参数 literal。
填写变更原因时不得粘贴敏感信息。单项文本最多 512 字符并标明省略，总 JSON 最大 32 KiB。

部署需先使用新版 Platform 应用 V33，或由 DBA 执行增量迁移；新库使用 sql/latest 完整包。
不通过重新查询当前资产填补历史，删除资源后已记录详情仍可查看。
